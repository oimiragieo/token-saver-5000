# Token Saver 5000 v0.2.0 Release Notes

**Release Date**: 2025-11-22
**Status**: Production-Ready
**Codename**: "Persistence & Polish"

---

## 🎉 Major Features

This release transforms Token Saver 5000 from a powerful in-memory MCP server into a **production-ready, persistent system** with robust resource management and enhanced dialogue capabilities.

### ✨ What's New

#### 1. **Persistent Storage Layer** 🗄️

**Problem Solved**: All data was lost on server restart, forcing re-ingestion of documents.

**Solution**: Full persistence layer with ChromaDB support and JSON fallback.

**Features**:
- ✅ ChromaDB integration for vector storage
- ✅ JSON/Pickle fallback when ChromaDB unavailable
- ✅ Auto-save documents on ingest
- ✅ Auto-load documents on server start
- ✅ Storage location: `.semantic_modulator_data/`
- ✅ Graceful degradation if persistence fails

**Impact**: Documents persist across server restarts. Work is never lost.

**New Files**:
- `src/persistence.py` (531 lines)

**Modified Files**:
- `src/server.py` - Integrated persistence manager
  * Added `_load_persisted_documents()` method
  * Updated `_handle_ingest()` to auto-save

---

#### 2. **Resource Management System** 📊

**Problem Solved**: No limits on document size or count, risking memory exhaustion.

**Solution**: Comprehensive resource management with configurable limits.

**Features**:
- ✅ Max document size: 100MB (configurable)
- ✅ Max total storage: 1GB (configurable)
- ✅ Max document count: 1000 (configurable)
- ✅ Max memory usage: 2GB (configurable)
- ✅ Pre-ingestion validation
- ✅ Warning thresholds (80% of limits)
- ✅ Resource statistics and health checks
- ✅ Cleanup suggestions when limits approached

**Impact**: System stability guaranteed. No more OOM crashes.

**New Files**:
- `src/resource_manager.py` (257 lines)

**Modified Files**:
- `src/server.py` - Integrated resource manager
  * Pre-ingestion size checks
  * Document registration/unregistration
  * Resource tracking

---

#### 3. **AFM Export/Import** 💾

**Problem Solved**: No way to save/restore conversation state for multi-session dialogues.

**Solution**: Export and import AFM conversation history.

**Features**:
- ✅ Export conversation to persistent storage
- ✅ Import conversation from storage
- ✅ Session ID support for multiple conversations
- ✅ Metadata tracking (export time, message count)
- ✅ List available sessions
- ✅ Automatic persistence integration

**Impact**: Long conversations can be paused and resumed across days.

**New MCP Tools** (2):
- `afm_export_history` - Save conversation state
- `afm_import_history` - Restore conversation state

**Modified Files**:
- `src/server.py` - Added export/import handlers
  * `_handle_afm_export_history()`
  * `_handle_afm_import_history()`

---

#### 4. **Document Discovery** 📚

**Problem Solved**: AI agents had no way to discover what documents were available.

**Solution**: New `list_documents` MCP tool.

**Features**:
- ✅ Lists all ingested documents with metadata
- ✅ Shows compression stats per document
- ✅ Displays author, date, tags if available
- ✅ Provides next-step suggestions
- ✅ Handles empty state gracefully

**Impact**: AI workflows improved - can now list → select → query.

**New MCP Tools** (1):
- `list_documents` - Get inventory of all documents

**Modified Files**:
- `src/server.py` - Added list_documents handler
  * `_handle_list_documents()`

---

#### 5. **Robust Token Counting** 🔢

**Problem Solved**: Token counter would crash if tiktoken unavailable, inconsistent with AFM.

**Solution**: Applied AFM's graceful fallback pattern to semantic_compressor.

**Features**:
- ✅ Primary: tiktoken (cl100k_base)
- ✅ Fallback: word count × 1.3 approximation
- ✅ Clear warning when falling back
- ✅ No runtime crashes
- ✅ Handles encoding failures

**Impact**: System works even without full dependencies. Better offline support.

**Modified Files**:
- `src/semantic_compressor.py` - Updated token counting
  * Added try/except in init
  * Modified `_count_tokens()` with fallback logic

---

#### 6. **Automated Installation** 🚀

**Problem Solved**: Manual MCP configuration was error-prone, required manual path editing.

**Solution**: Automated installation script.

**Features**:
- ✅ Auto-detects OS (macOS/Linux/Windows)
- ✅ Locates Claude Desktop config automatically
- ✅ Generates MCP config with correct paths
- ✅ Safely merges with existing config
- ✅ Creates backup before modification
- ✅ Updates existing entry if present
- ✅ Clear next-step instructions

**Impact**: Setup time reduced from ~5 minutes to ~30 seconds.

**New Files**:
- `install_mcp.sh` (143 lines, executable)

## 🔧 Technical Improvements

### Persistence Architecture

```
.semantic_modulator_data/
├── chromadb/              # ChromaDB vector store (if available)
│   └── [collections]/
├── documents/             # Document metadata & graphs
│   ├── doc1.pkl
│   ├── doc1_graph.pkl
│   └── doc2.pkl
└── afm_history/          # AFM conversation states
    ├── default.pkl
    └── session123.pkl
```

### Resource Management Flow

```
User: ingest_context(large_doc)
  ↓
ResourceManager.check_document_size()
  ↓ [if exceeds limit]
ValueError: "Document too large: 150MB exceeds limit of 100MB"

  ↓ [if within limit]
SemanticCompressor.ingest_file()
  ↓
ResourceManager.register_document()
  ↓
PersistenceManager.save_document()
  ↓
Success!
```

### Auto-Load/Save Flow

```
Server Start:
  ↓
_load_persisted_documents()
  ↓
For each file_id in persistence.list_documents():
  ↓
  Load chunks, graph, metadata
  ↓
  Register with resource_manager
  ↓
  Restore to compressor
  ↓
Ready! (Documents restored)

Document Ingest:
  ↓
_handle_ingest()
  ↓
Check resource limits
  ↓
compressor.ingest_file()
  ↓
persistence.save_document()  # Auto-save!
  ↓
Success! (Document persisted)
```

## 📋 Migration Guide

### From v0.1.0 to v0.2.0

**For Users**:
1. Pull latest code: `git pull origin main`
2. Install dependencies: `pip install -r requirements.txt`
   - ChromaDB added (optional, has JSON fallback)
   - psutil added (optional, for memory monitoring)
3. Run setup check: `python check_setup.py`
4. Optional: Use `./install_mcp.sh` for automated config

**For Developers**:
1. Import new modules if needed:
   ```python
   from src.persistence import PersistenceManager
   from src.resource_manager import ResourceManager, ResourceLimits
   ```

2. Optionally configure resource limits:
   ```python
   limits = ResourceLimits(
       max_document_size_mb=200.0,  # Increase if needed
       max_total_storage_mb=2048.0,
       max_documents=2000
   )
   resource_manager = ResourceManager(limits)
   ```

3. All existing code works as-is!

## ⚡ Known Limitations

### Current Limitations (Acknowledged)

1. **Single Process**
   - No multi-process support yet
   - All operations synchronous
   - Plan: v0.3.0 will add async operations

2. **No Incremental Updates**
   - Cannot update existing documents
   - Must re-ingest entirely
   - Plan: v0.3.0 will add diff/patch support

3. **ChromaDB Optional**
   - Falls back to JSON if ChromaDB unavailable
   - JSON fallback is slower for large collections
   - Recommendation: Install ChromaDB for production

4. **No Cross-Document Search**
   - `search_semantic` requires file_id
   - Cannot search across all documents at once
   - Plan: v0.3.0 will add global search

## 💡 Usage Examples

### Example 1: Persistent Documents

```python
# Session 1: Ingest a document
AI: ingest_context(large_manual, "user_manual_v1")
# Document auto-saved to .semantic_modulator_data/

# Server restarts...

# Session 2: Document auto-loaded!
AI: list_documents()
# Shows: user_manual_v1 (auto-loaded from storage)

AI: read_skeleton("user_manual_v1")
# Works immediately, no re-ingestion needed!
```

### Example 2: AFM Export/Import

```python
# Long conversation about project planning
AI: afm_add_message("user", "Let's plan the Q4 roadmap")
# ... 20 turns of detailed planning ...

AI: afm_export_history(session_id="q4_planning")
# Conversation saved

# Next day...
AI: afm_import_history(session_id="q4_planning")
# Full conversation context restored!

AI: afm_build_context("What did we decide about the API redesign?")
# Builds context from restored history
```

### Example 3: Resource Limits

```python
# Try to ingest huge document
AI: ingest_context(500MB_pdf, "giant_doc")

# Response:
# ❌ Error: Document too large: 500MB exceeds limit of 100MB
# 💡 Tip: Split document into smaller sections or increase max_document_size_mb

# Split into smaller parts
AI: ingest_context(part1, "giant_doc_part1")  # ✅ 80MB - OK
AI: ingest_context(part2, "giant_doc_part2")  # ✅ 75MB - OK
```
